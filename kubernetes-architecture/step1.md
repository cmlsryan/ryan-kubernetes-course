# 先理解 Kubernetes 在做什麼

## 先回答，不要急著看答案

公司有很多台 Server，每台 Server 都在執行 Container。

其中一台 Server 故障時，哪一種做法比較適合大型系統？

**A.** 管理員每天逐台檢查，故障後再手動處理  
**B.** 使用一套統一系統，持續觀察整體狀態並協調工作

---

## Kubernetes 的角色

比較接近 **B**。

Docker 或 Container Runtime 主要負責在**單一主機**上執行 Container。

Kubernetes 則負責在由多台機器組成的環境中，編排與維持容器化工作負載。

它會持續比較：

```text
我們希望的狀態
        ↓
目前真正的狀態
        ↓
不一致時，相關控制元件嘗試調整
```

初學階段可以先記住：

> **Kubernetes 是管理與協調容器化工作負載的系統，不只是用來「看」哪裡壞掉。**

---

## 用物流公司建立架構畫面

```text
Cluster：整套物流系統
│
├── Node：一座加入系統的倉庫
│   └── Pod：被安排在倉庫中的一組工作
│       └── Container：真正執行程式的工作人員或機器
│
└── Scheduler：總部的調度員，替尚未分配位置的 Pod 選擇 Node
```

### 比喻的限制

這只是協助理解：

- **Node** 真正是一台實體機或虛擬機，不是真的倉庫。
- **Pod** 是 Kubernetes 的部署與排程基本單位，不是真的貨物。
- **Container** 是隔離執行程式的環境，不是真正的人。
- **Scheduler** 會依照資源需求與排程規則選擇合適的 Node，不是單純選「看起來最閒」的機器。
